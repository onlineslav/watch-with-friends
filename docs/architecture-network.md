# Architecture: friends, Trystero patch, rejoin repairs

Moved word for word from CLAUDE.md on 2026-11-12 so a session doesn't load it every turn. Read before touching `renderer/friends.mjs`, `scripts/patch-trystero.js`, `renderer/peer-stream.mjs`, or how peers connect.

- **Friends** (`renderer/friends.mjs`, `FriendNetwork`, protocol tested against an in-memory Trystero in `test/friends.test.mjs`): no server. There's one friends list (`#friends`): it slides in from the left on home and floats over the video on the left in a room (`enterRoom`/`leaveRoom` move it, `setFriendsOpen` toggles it; the room list's "Invite friends" opens it too). It shows your username to copy, and the toggles' dot means a friend is online (green) or a request is waiting (accent). Each app waits in `inbox:<username>`. Adding someone joins `pair:<a>:<b>` (sorted) and, until they acknowledge the request, their inbox. Accepting a request adds them back, so both meet in the pair room. Every peer must first send a hello signed over the room id and both peer ids (`helloText`, `verifySigned`); other messages from unverified peers are queued until then. Presence rides on the pair room's `profile` message (`status: {inRoom, hosting, title}`, cleaned by `cleanStatus`); `syncPresence` in `app.js` resends it whenever your status changes, and it's forgotten as soon as the friend goes offline. Asking to join uses the pair room's `join` message (`ask`, then `invite` with the room code or `declined`); an answer is only honoured if you asked that friend within the last 2 minutes, so nobody can pull you into a room. Inviting a friend from inside your room sends `offer` with the code (`inviteToRoom`); it only shows them a card (`receiveJoinOffer`), and they join if they click Join. Trystero's `selfId` is the same in every room, so anything keyed by peer id must also check which room it came from.
- **Trystero transport patch (pinned 0.25.4):** `scripts/patch-trystero.js` runs after installation and before tests/bundling. It prevents departed-room frame replay, bounds reassembly and handshake queues, expires abandoned chunks, and reports stalled sends. A connection still "disconnected" after Trystero's 5s deadline is now closed, not just reported: on a shared connection nothing else closed it, so it recovered with this side's rooms gone while the other side never noticed (a viewer stuck on a frozen frame for 9 minutes). `test/transport.test.mjs` covers the actual dependency; `npm run test:network` checks repeated rejoining while friend connections stay alive. **Ghost attach (M1.7, marker `watch-with-friends ghost attach v1`):** someone leaving a room says `@_leave` on the data channel, but a shared peer's relay announcements and offers travel another way, and one sent just before the leave could arrive just after it; `attachSharedPeerToRoom` then bound a peer that was no longer in the room, and when they really came back their presence frame found the binding already there, nobody started the new visit's handshake and everyone timed out after 10 s (found by `--churn-loop`, and by the 0.8.2 Mac CI run). Now after a `@_leave` only a presence frame (or a new connection) may attach that peer again; signals are ignored for 5 s (`leftRoomAt` in `strategy.mjs`; `room.mjs` hands `onPeerLeave` the reason). A copy that never sends presence frames cannot leave a room this way either, which is why this rule is `[wire]`: run `npm run test:compat` against old copies. Review these patches before upgrading the dependency.
- **Repairs found by looping the rejoin (M1.7):** `renderer/peer-stream.mjs` (`repairedStream`): over a kept connection the room can hand a viewer a stale `MediaStream` for the host (the film was taken off and put back while they were away; the transport matched the announcement to the first stream it ever saw for that id), so the sound or the picture is missing while the receivers carry both; `refreshPeerStream` in `app.js` checks the stream against the connection's receivers and builds one from their tracks (log `media/peer-stream-repaired`). `renderer/sender-parameters.mjs` (`applySenderParameters`): `tuneSenders` reads `getParameters()` right before `setParameters()` and, if a renegotiation landed in between ("modified RTCP parameters", `InvalidModificationError`), reads again and retries once (`send-parameters-applied` carries `retried: true`; the once-a-second pass is the backstop). `renderer/source-buffer.mjs` (`whenIdle`): `player.mjs` waits for `SourceBuffer.updating` to be false, not for one `updateend` (`abort()` queues one of its own, which satisfied the wait while a `remove` still ran and the seek's `timestampOffset` threw). Publishing failures are no longer swallowed: `media/publish-failed` (one per peer) and `media/replace-track-failed`. `scripts/temp-dirs.js` removes the bench's and `test:network`'s scratch folders when a run ends and stale ones when one starts (they once filled the disk); `check-network.js` takes `--rejoin-loop=N`, `--churn-loop=N` and `--switch-loop=N` to repeat those steps.
